# Публикация Lili на GitHub

Для первой публичной загрузки используйте **чистую экспортированную папку** или распакованный архив с ней. Старый рабочий репозиторий содержит сторонние движки, модели и локальные настройки в истории коммитов. Добавление `.gitignore` не удаляет их из истории и не отменяет отслеживание уже добавленных файлов.

## Получить чистую копию

В рабочем проекте выполните:

```powershell
npm run export:github
```

Путь к новой папке будет напечатан в терминале. Скрипт копирует текущие файлы с диска, включая ещё не закоммиченные изменения. В копию входят исходники `src/`, `electron/`, выбранные скрипты, конфигурация сборки, lockfile, документация и лицензия.

В неё не входят `.git`, настройки редакторов и AI-инструментов, `node_modules`, результаты сборки, сторонние репозитории, движки, модели, записи микрофона и личные данные. Новые типы исходных ресурсов нужно явно добавить в `scripts/export-github.mjs`. Перед повторной публикацией просмотрите изменения: скрипт выбирает пути, но не распознаёт все возможные секреты внутри исходного кода.

## Загрузить через Git

1. Создайте на GitHub пустой репозиторий с видимостью **Public**. Не добавляйте на сайте README, `.gitignore` или лицензию: они уже есть в проекте.
2. Скопируйте чистую папку в отдельное место вне старого репозитория и откройте в ней PowerShell. Не переносите туда старую папку `.git`.
3. Выполните команды ниже, заменив `YOUR_USERNAME` и `YOUR_REPOSITORY` своим именем и названием репозитория.

```powershell
git init -b main
git add .
git status --short
git commit -m "Initial public release"
git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git
git push -u origin main
```

Если Git просит указать имя и email, настройте их в этой новой папке перед коммитом. Для публичных коммитов можно использовать свой GitHub noreply-адрес из настроек аккаунта; не подставляйте личный email, если не хотите его публиковать.

## Загрузить через сайт

Создайте репозиторий **Public**, выберите загрузку существующих файлов и загрузите содержимое чистой папки с сохранением каталогов. Если используете ZIP, сначала распакуйте его: для просмотра кода на GitHub нужны сами файлы, а не единственный архив. Убедитесь, что `.gitignore` и `.gitattributes` тоже загружены.

Рабочая папка с моделями и исходная история Git остаются локально. После публикации продолжайте работу с новым репозиторием или переносите в него проверенные изменения; отправка старых веток снова перенесёт старую историю.
