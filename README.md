# Lili — локальный AI-ассистент для Windows

Настольный помощник с текстовым чатом, голосовым вводом, озвучиванием ответов и командами для повседневных задач. Интерфейс написан на React и TypeScript, приложение работает в Electron.

Чат использует **Qwen3-4B GGUF через llama.cpp**, распознавание речи — **whisper.cpp**, синтез речи — **Piper**. Вычисления этих моделей выполняются на компьютере пользователя. Погода, веб-поиск, YouTube и внешние приложения могут обращаться к сети.

## Возможности

- Чат с потоковыми ответами и Markdown.
- Голосовой ввод на русском и английском, активация словом «Лили».
- Озвучивание ответов с переключением языка.
- Память диалога, заметки, задачи, дневник и напоминания.
- Создание и чтение файлов в отдельной рабочей папке.
- Управление приложениями, громкостью, медиаплеером и окнами Windows.
- Погода, веб-поиск и работа с буфером обмена.

Подробный справочник команд: [LILI_ABILITIES.txt](LILI_ABILITIES.txt). Он также содержит историю прежних версий; актуальная схема запуска приведена ниже.

## Быстрый старт

Нужны Windows x64, Node.js 22 и npm. Команды выполняются в PowerShell из корня проекта.

```powershell
npm ci
npm run dev
```

Без дополнительных движков и моделей интерфейс запускается, но AI-ответы и голосовые функции требуют настройки ниже. Модели, исполняемые файлы, DLL и пользовательские данные в репозиторий не включены.

### Модель чата

1. Скачайте Windows x64 сборку из [релизов llama.cpp](https://github.com/ggml-org/llama.cpp/releases). Поместите `llama-server.exe` вместе с DLL из архива в `llama.cpp/bin/`.
2. Скачайте квантованную модель Q4_K_M из [Qwen3-4B-GGUF](https://huggingface.co/Qwen/Qwen3-4B-GGUF). Положите её в `Qwen3-4B-GGUF/Qwen3-4B-Q4_K_M.gguf` либо укажите путь через `QWEN_GGUF_MODEL`.
3. Запустите `npm run dev`. Приложение запускает сервер на `127.0.0.1:18080`.

Используйте сборку llama.cpp, поддерживающую параметры `--jinja`, `--reasoning off`, `--reasoning-format none` и `--no-webui`. Они заданы в `electron/qwenManager.ts`; при несовместимости проверьте вывод сервера в терминале.

Ollama для текущего чата не требуется. Названия некоторых IPC-каналов и файлов с `ollama` сохранены от предыдущей реализации. `scripts/qwen_worker.py` — альтернативный Python worker, основной запуск приложения его не использует.

### Распознавание речи (необязательно)

Скачайте Windows сборку из [релизов whisper.cpp](https://github.com/ggml-org/whisper.cpp/releases) и поместите `whisper-cli.exe`, `whisper-server.exe` и необходимые DLL в `whisper/`.

Модели whisper.cpp помещаются в `whisper/models/`. Приложение распознаёт имена `ggml-base.bin`, `ggml-small.bin`, `ggml-medium.bin` и `ggml-large-v3-turbo-q5_0.bin`. Для начала достаточно `ggml-base.bin`; путь к другой модели можно задать через `WHISPER_MODEL`. Разрешите приложению доступ к микрофону в Windows.

### Озвучивание (необязательно)

Приложение рассчитано на CLI Piper с `piper.exe`, например из [релизов rhasspy/piper](https://github.com/rhasspy/piper/releases). Сохраните рядом с ним DLL и каталог `espeak-ng-data` из дистрибутива.

Ожидаемая структура локальных ресурсов:

```text
llama.cpp/bin/llama-server.exe
Qwen3-4B-GGUF/Qwen3-4B-Q4_K_M.gguf
whisper/whisper-cli.exe
whisper/whisper-server.exe
whisper/models/ggml-base.bin
piper/piper.exe
piper/models/en_US-lessac-medium.onnx
piper/models/en_US-lessac-medium.onnx.json
piper/models/ru/ru_RU-irina-medium.onnx
piper/models/ru/ru_RU-irina-medium.onnx.json
```

Для каждого голоса Piper нужны и модель `.onnx`, и соответствующий `.onnx.json`. DLL и вспомогательные файлы движков в схеме не перечислены, но также нужны для запуска.

### Свои пути

Можно хранить модели вне проекта. Укажите абсолютные пути в переменных среды **до запуска**. Например:

```powershell
$env:LLAMA_SERVER_BIN = 'D:\AI\llama\llama-server.exe'
$env:QWEN_GGUF_MODEL = 'D:\AI\models\Qwen3-4B-Q4_K_M.gguf'
npm run dev
```

| Переменная | Назначение |
| --- | --- |
| `LLAMA_SERVER_BIN` | Сервер llama.cpp |
| `QWEN_GGUF_MODEL` | Модель чата GGUF |
| `WHISPER_BIN` | whisper-cli.exe |
| `WHISPER_SERVER` | whisper-server.exe |
| `WHISPER_MODEL` | Модель распознавания речи |
| `PIPER_BIN` | piper.exe |
| `PIPER_MODEL_EN` | Английский голос ONNX |
| `PIPER_MODEL_RU` | Русский голос ONNX |
| `LILI_WORKSPACE_DIR` | Рабочая папка создаваемых файлов |

Главный процесс Electron читает системные переменные среды; автоматическая загрузка этих значений из `.env` не настроена.

## Данные пользователя

История чата, память, заметки, задачи, контакты, дневник, журнал команд и снимки экрана сохраняются в каталоге Electron `userData`. В режиме разработки на Windows это обычно `%APPDATA%\lili`; точное имя зависит от имени приложения.

Файловая рабочая папка по умолчанию — `draftforlili/` в корне проекта при разработке, а в установленном приложении — `draftforlili/` внутри `userData`. Её можно изменить через `LILI_WORKSPACE_DIR`.

Эти данные исключены из экспортируемой копии. Не переносите их в исходники и не прикладывайте логи с личной перепиской к публичным обсуждениям. Команды управления системой выполняются с правами текущего пользователя.

## Разработка

```powershell
npm run typecheck
npm run build
```

- `src/` — React-интерфейс, компоненты и хуки.
- `electron/` — главный процесс, IPC, модели, хранение данных и системные команды.
- `scripts/` — вспомогательные инструменты.
- `LILI_ABILITIES.txt` — справочник команд.

`npm run dist` собирает установщик Windows через electron-builder. Текущая конфигурация включает только приложение: локальные движки и модели в установщик автоматически не копируются. Для установленного приложения задайте внешние пути через переменные среды либо подготовьте ресурсы отдельно. Системные команды ориентированы на Windows; поддержка других ОС не проверена.

## Публикация

```powershell
npm run export:github
```

Команда создаёт новую папку `exports/lili-github-<дата>/` из исходников и документации, без старой Git-истории. Она не удаляет рабочие файлы. Инструкция по загрузке: [PUBLISHING.md](PUBLISHING.md).
